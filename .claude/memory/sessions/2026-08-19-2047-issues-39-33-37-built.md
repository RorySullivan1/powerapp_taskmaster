## Gotchas & dead ends
- **`ForAll` + `Concurrent` is legal here ONLY because the bodies `Collect`.** The 2026-08-19
  ForAll/Set restriction (MS Learn sanctions Patch and Collect, rules out Set/UpdateContext/
  ClearCollect because rows may run in any order) does not bite — but it is exactly the rule a
  future "simplification" to `Set` would break. Comment says so in-place.
- **#37's ticker merge is staged through `colPdUndMerge` on purpose.** The obvious shape,
  `ClearCollect( colPdUndAll, Sort(Distinct(... colPdUndAll ...)) )`, reads the collection it is
  filling. Nothing across the gap can tell us whether that is safe, so it is not used: copy out,
  add, rebuild. Three local statements, zero server calls.
- **The Sort in that merge is LOAD-BEARING, not cosmetic.** `galPdUndSug.Items` is
  `FirstN( Filter(colPdUndAll, ...), 12 )`, so a ticker appended to an unsorted tail would never
  appear in the chips — which is the exact thing #37's "Done when" asks to see.
- **`Distinct` renames the column to `Value`.** `colPdUndAll` is built on that, so the merge must
  end in a `Distinct(..., Tk)`-shaped step or the schemas diverge. This is why the merge rebuilds
  through `Distinct` rather than `Collect`-ing `{Tk: ...}` records.
- **#40 was deliberately kept out of this batch.** It is trivial, but it touches `App.OnStart`
  (formula-bar-only — a different transfer mechanism) plus two screens, for ZERO behaviour
  change. A batched paste returns ONE binary works/doesn't, so bundling a silent guard with two
  real changes makes a failure signal ambiguous about its cause.
- **#40's body is now stale**: it says six `>= 2000` literals with #30 proposing a seventh. #30
  landed, so there are seven live (`scrHome:127` joined the six in `gRptTrunc`). Correct the body
  when it is taken, and take it BEFORE #34 so a #34-option-2 sentinel uses the constant.
- **#38 deferred, not skipped.** Authorable, but it rewrites the destructive path (guard counts
