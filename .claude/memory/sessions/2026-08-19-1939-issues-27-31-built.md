## Gotchas & dead ends
- **The `"(none)"` sentinel defeats an `IsEmpty` guard.** scrTaskEdit's five output lists add
  their own `"(none)"` row, so a `Choices()` that returned nothing still leaves the list
  non-empty: `IsEmpty` would latch a one-option dropdown for the whole session and every save
  would write Blank() from it. Those five guard on **`CountRows(col) <= 1`**. The other 15
  carry no sentinel row, so `IsEmpty` is right for them. Do not "make them consistent".
- **A Concurrent arm is ONE formula**, so the two-statement builds
  (`ClearCollect(col, {sentinel}); Collect(col, ForAll(...))`) had to become one
  `ClearCollect( col, {sentinel}, ForAll(...) )` — ClearCollect takes several items, and order
  is preserved so "(none)" still sorts to the top.
- **Concurrent changes the failure mode, deliberately**: arms fail independently, so a failed
  `Choices()` no longer stops the whole OnVisible. Strictly better, but it retires the
  "order is defensive" comment on scrTaskEdit, which was rewritten rather than deleted.
- Verified before caching: all 20 collections have **exactly one write site** each, so nothing
  elsewhere can Clear a cached list mid-session.
- **Left alone on purpose:** the health-recompute block still reads the raw `taskmaster_issues`
  (its body must stay identical across scrProject and scrIssueEdit, and it runs on scrIssueEdit
  where the collections do not exist); the per-click delete-reference counts still query live
  (a delete guard must not read a snapshot); the delete cascade's three counts are #38's scope.
- `colMapRegion` (scrProjectEdit) and `colMapRegionCl` (scrClientEdit) hold the SAME
  `mapping_regions` list under two names — now one fetch each per session rather than one per
  visit, so not worth the cross-screen churn to unify. Left as is.
