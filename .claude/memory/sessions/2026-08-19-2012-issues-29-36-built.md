## Gotchas & dead ends
- **The mirror LookUp's key changed from `gSelProject.ID` to the screen's own parent id**
  (`gTkProject.Id` / `gIssProject.Id`). Merging two LookUps forces one key, and the screen-local
  one is strictly more correct: it is the record's OWN stored parent, where `gSelProject` is only
  equal to it because every entry path happens to come from that project. Both entry paths into
  `scrTaskEdit` (`scrProject`, `scrProjectEdit`) were checked. The "read LIVE, never a snapshot"
  invariant is untouched — the id is a key, the record is still fetched at save time.
- **`scrTransactionEdit` was deliberately NOT changed**, despite #29 naming it. It has exactly ONE
  pre-Patch read and nothing independent to pair it with, so hoisting the LookUp out of the Patch
  record moves code without removing a round trip. Same shape of call as #31's skip there.
- **`Concurrent` needs ≥ 2 arms** — that is why the rollup block became a bare `Set`, not a
  one-armed `Concurrent`.
- **`If(cond, value)` with no else** is how the conditional close-date arm stays conditional
  inside a `Concurrent` arm; it yields `Blank()` when false, which `Coalesce(..., Now())` already
  handles.
- **`task_product_summary` is now left unwritten on a products-untouched save**, so a brand-new
  task with no products keeps `Blank()` where it used to get `""`. No control in `src/` reads that
  column (checked) — it is a denormalised column for SharePoint views — so blank vs empty string
  is not observable in the app.
- **The `tglTkOutput` trap stays fixed.** The gate compares staged state to loaded state, never
  toggle visibility, so deliberately clearing every product is still a set difference and still
  deletes.
