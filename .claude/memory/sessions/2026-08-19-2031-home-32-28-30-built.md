## Gotchas & dead ends
- **`Select()` QUEUES the target `OnSelect` for AFTER the calling formula finishes** — it does not
  run it inline and does not wait (MS Learn, function-select). Two consequences, both commented
  in the source: the `OnVisible` self-heal is GUARANTEED to land before the fold reads
  `gUserEmail`; and **the Refresh toast now fires BEFORE the numbers do** — "Refreshed" means the
  refresh was issued. Moving the toast into `btnHomeRecompute` would fix the order but would then
  toast on every screen open, so it stays in `OnAction`. Keep `Select` LAST in both callers.
- **The one unresolved paste-time question:** `Select()` of a screen control named from a
  COMPONENT INSTANCE's event handler (`hdrMyWork.OnAction`). No prior case in the repo — every
  existing `Select( btnRptLoad )` / `Select( btnPrjRecompute )` caller is a screen `OnVisible`,
  `OnChange` or a plain control `OnSelect`. The handler is authored in SCREEN scope (component
  isolation applies to formulas INSIDE the component definition, not to the instance's event
  binding), and none of the four documented `Select` restrictions bite: same screen, target has
  `OnSelect`, behaviour formula, no self-Select cycle. **If Studio rejects it, the fallback is to
  inline the fold in `OnAction` again while keeping `OnVisible` on the button** — half the win,
  no risk.
- **#28's archived-parent edge was ACCEPTED, not solved.** `colPrjNames` covers active projects
  only, so a row whose parent archived since its `*_project_archived` flag was last stamped shows
  "—" instead of a name; today's raw-list LookUp resolves it. Considered and REJECTED a
  `If( IsBlank(local), <server LookUp> )` fallback: `If` laziness is grounded in BEHAVIOUR
  formulas, but this is a DECLARATIVE `Text` property where the row may still register the data
  source dependency — a construct that MIGHT not remove the per-row call is worse than one that
  definitely does, when the goal of the issue is removing per-row calls and nothing can be
  measured across the gap.
- **#30 amends the 2026-08-13 decision, it does not reverse it.** There is still no delegable
  single query for "children of the projects I manage" and `issue_project_id.Id in
  colMyProjects.ID` still does not delegate. What changed is the guard: the `>= 2000` sentinel
  means a partial page can no longer undercount silently, which is the risk that decision was
  protecting against. Both `If` arms are live; the comment says so, so neither reads as dead
  code later.
- **`ForAll` projection, never `ShowColumns`, over anything rooted in a named formula** — both
  new collections read a field back, so both use `ForAll`. `colRptIss` on `scrReports` gets away
  with `ShowColumns( OpenIssues, ... )` only because nothing reads a column off it.
- **The three `LookUp( taskmaster_projects, ... )` left in `scrHome` row `OnSelect` handlers are
  correct and out of scope** — one call per TAP, and a deliberate live re-read before navigating
  (rule 5 in the screen header).
