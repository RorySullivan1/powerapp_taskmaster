## Gotchas & dead ends
- **I TOLD THE USER #34 WOULD COST ONE PREDICATE PER BRANCH. THAT WAS WRONG, and it was wrong
  against a rule already in this ledger.** `StartsWith(col, "")` is BANNED here — #17 built the
  lead filter on it, it returned NOTHING for every choice in the app (#19), and the ledger entry
  says an "off" state must be a BRANCH, not a predicate claiming to match everything. So the
  search dimension DOUBLES the tree: `galProjects.Items` is now **16 branches**
  (search × show-completed × coverage × only-mine), 16 `Filter( ActiveProjects` shapes.
  Corrected to the user before building. **Do not re-derive the cheap version.**
- The alternative offered and NOT taken: let a search OVERRIDE the other filters, which would be
  ~10 branches instead of 16. Rejected because today's outer `in` filter composes WITH the
  filters, and preserving current composition semantics is the faithful choice. Available if the
  formula size ever becomes the bigger problem.
- **`StartsWith` goes INSIDE each existing branch, never in place of one** — a bare
  `Filter(ActiveProjects, StartsWith(...))` without an explicit phase group drew "the query is
  not valid" from SharePoint.
- **#38's counts could not stay in the `With`.** `Concurrent` takes BEHAVIOUR formulas, so each
  count has to land in a global before the threshold test can read it.
- **`Coalesce` skips an empty string as well as a blank**, which is what lets the three per-arm
  error globals be seeded `""` without masking a real message.
- Kept the `IfError( Set( scrap, RemoveIf(...) ), ... )` wrapper verbatim on the destructive path
  even though the scrap globals are write-only. Tidying it is a separate change and this is not
  the paste to make it in.
- **A ` #` INSIDE A PLAIN (NON-BLOCK) YAML SCALAR IS EATEN AS A COMMENT, AND
  `tools/validate_pa_yaml.py` DOES NOT CATCH IT.** `Text: ="… issue #35"` parsed to
  `="… issue` — quote and all gone — and the validator said `ok`, because by the time it sees the
  parsed doc the `#` no longer exists; its `stray_hash_errors` check only finds a `#` that
  SURVIVED parsing (i.e. inside a block scalar). `tools/balance_check.py` caught it as an
  unterminated string. **Use a block scalar for any formula containing `#`.**
