# 3 · Projects

## Finding a project

The **Projects** screen is one gallery with a single filter row above it:

- **Search** — matches from the **start** of the project name. Typing `lon` finds *London
  review* but not *Review, London*. This is a limitation of what SharePoint can filter quickly,
  and it means the whole list stays searchable however long it grows.
- **Coverage** — narrows to one business/product coverage area.
- **Only show my projects** — projects where you are the manager.
- **Show completed** — off by default, so the browser shows live work. Turn it on to see
  finished projects.

Selecting a row opens the project.

## The project screen

The top of the screen is the project's **information card** — manager, coverage, region, project
type, priority, status, started and target dates — beside a **completion ring**.

**The ring is calculated, not entered.** It is the weighted average of the stages of the
project's tasks: a task in *Planning* contributes little, one in *Finalizing* contributes most,
a *Completed* one contributes fully. Move a task's stage and the ring moves. There is no field
anywhere that sets the percentage directly.

Below the card, the project's work is laid out in three panels:

| Panel | Contents |
|---|---|
| **Tasks** | The work items on this project |
| **Transactions** | The trades booked against it |
| **Issues** | What is going wrong on it, full height on the right |

Each panel has its own **＋ New** button and its own empty-state sentence. Selecting a row opens
that item for editing; the delete icon at the end of a row removes it, after confirming.

## Marking a project complete

**✓ Mark complete** closes the project out. Completed projects drop out of the Projects browser
unless **Show completed** is on, and they drop out of the desk-wide reports of live work.

## Editing a project

Opening a project for edit gives you its details, classification (coverage, region, project
type), people, dates, priority, description and shared-drive path. The edit screen can also
**stage tasks and transactions** alongside the project itself, so a new project can be created
with its first work already attached rather than in three separate visits.
